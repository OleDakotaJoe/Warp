# Templates

Copy the sections that clarify the task, then remove unused guidance. Do not create every template for every change. Keep real authority and evidence links in adopted documents.

| Template | Use |
| --- | --- |
| [AGENTS entrypoint](AGENTS.template.md) | Route a coding assistant into the local hierarchy |
| [Product](product.template.md) | User problem, outcome, scope, non-goals |
| [Requirements](requirements.template.md) | Behavior, required mechanisms, acceptance |
| [Design](design.template.md) | Data flow, boundaries, alternatives, compatibility |
| [Decision](decision.template.md) | Accept or supersede a meaningful choice |
| [Recon](recon.template.md) | Evidence-backed map before changing an existing system |
| [Plan](plan.template.md) | Sequence multiple reviewable slices |
| [Slice](slice.template.md) | Execute a small change with explicit acceptance |
| [Test plan](test-plan.template.md) | Coordinate verification across boundaries |
| [Verification](verification.template.md) | Show requirement-level evidence and gaps |
| [Experiment](experiment.template.md) | Evaluate a hypothesis or required mechanism |
| [Philosophy](philosophy.template.md) | Add a scoped rule with enforcement and tradeoffs |
| [Interface design](interface.template.md) | Human-facing states, accessibility, and recovery |

Metadata: document state is draft/accepted/superseded/archived; implementation state is separate. Record the accepting decision or instruction instead of having an assistant invent approval.
