# WARP: development instructions

Start at the [development index](docs/development/index.md), [constitution](docs/development/constitution.md), and [project profile](docs/development/project-profile.md). Follow the profile's links to the existing canonical owners. Read only applicable philosophies and task documents.

These instructions govern development sessions. They do not automatically configure workers inside the software. Respect the user's current instructions and authorization; a mode or document does not grant extra permission.

Choose EXPLORE for discovery, EXPERIMENT for an uncertain hypothesis, DESIGN for architecture, STRICT MODE for the accepted implementation task, and REVIEW for evidence assessment. See the [mode router](docs/development/modes/index.md).

In STRICT MODE, preserve accepted behavior and required mechanisms. Surface material ambiguity, omissions, and doc/code discrepancies. Handle routine reversible implementation choices within the task autonomously. Do not weaken requirements or tests to make an incomplete implementation appear complete.

Use a task-sized [lifecycle](docs/development/guides/lifecycle.md). Finish substantial work with requirement-level implementation/evidence, actual checks, deviations, and next actions. Keep canonical docs current; use the [extension process](docs/development/guides/extending.md) for intentional policy changes.
